# prompt-regression

推奨の設定: gpt-6-luna・medium。比べ方は AGENTS.md の「モデルと effort の案内」

## 1. ケースと実行手段を確かめる

- ケース: そのリポジトリの `prompt-cases/` などにある cases ファイル。形は `scripts/check_outputs.py` の冒頭の説明。
  無ければここで止め、形を示して、過去の不具合や代表的な入力から作るかをユーザーに聞く。リポジトリにファイルを足すのはユーザーが決めてから。
- 実行手段: そのプロジェクトがモデルを呼ぶのに使っているスクリプトや関数。見つからなければ聞く。自前でモデルの呼び出しを書かない。

## 2. 呼ぶ前に承認を取る

呼び出しの回数（ケース数 × 2）、送る内容（入力にお客様のデータや社外秘が含まれるか）、使うモデルと設定を見せて承認を取る。

## 3. 出力を作る

- 変更前のプロンプトは `git show <base>:<path>` で一時ディレクトリに書き出すか、一時ディレクトリに `git worktree add` して使う。**作業ツリーを stash や checkout で動かさない**（未コミットの変更を守るため）。
- 変更前と変更後で、モデル・温度などの設定を同じにする。
- 出力は `<出力ディレクトリ>/<case id>.txt` に保存する（UTF-8）。

## 4. 判定する

```powershell
python "$HOME\.agents\skills\prompt-regression\scripts\check_outputs.py" cases.json out-after --baseline out-before
```

- `regressions` があれば最優先で報告する。落ちたケースは 1 回だけ再実行して、毎回落ちるのか揺れなのかを分ける。
- 条件はどれも通ったのに出力が大きく変わったケースは、変更前後の出力を並べて見せ、意味の判断はユーザーに任せる。
- 全文一致を合否にしない。
