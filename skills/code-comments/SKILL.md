# コード内のコメント

推奨の設定: gpt-6-luna・low。比べ方は AGENTS.md の「モデルと effort の案内」

**HEAD のコードだけを見る同僚に向けて書く。**その人は会話も PR も diff も持っていない。

## 書かないもの

- 変更の経緯。「以前は」「今は」「〜へ変更した」「一時的に」。履歴は git が持つ
- レビュアーへの語りかけ。「これで正しく処理される」「ご指摘のとおり」は PR 本文のもの
- コードを読めば分かること。変数名や処理の言い換え
- 要件 ID・Issue 番号・PR 番号。コードにもテスト名にも書かない。トラッカーは移行で参照が切れる

## 書くもの

コードから復元できないことだけを書く。

- 他所で強制されている制約（DB の CHECK 制約、一意索引、呼び出し側との契約、外部 API の仕様）
- 微妙な境界条件と、順序に意味があること
- 壊れると実害が出る選択の理由。なぜ素朴な書き方を採らなかったか
- 実測で分かった、ドキュメントに無い挙動

## 編集するとき

言い換えや経緯へ退化したコメントは、その場で消す。これはその変更の一部であって、
スコープ外ではない。ただし頼まれていない限り、**変更していないコードへ新しくコメントを足さない** ——
依頼された範囲を越える。
