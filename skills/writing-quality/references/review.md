# 独立のレビュー

Step 5 の 2 段目で `prose-reviewer` に頼むときの、依頼の形と返す形。

## 起動のしかた

`spawn_agent` を `agent_type: "prose-reviewer"`、`fork_turns: "none"`、`task_name: "prose_review"`（2 回目からは末尾を変える。英小文字・数字・`_` だけ）、`message` に下の「渡すもの」を入れて呼び、`wait_agent` に `timeout_ms: 600000` を渡して返答を待つ。
**`fork_turns` を省かない。**省くと既定の `"all"` になり、親の会話を全部引き継ぐ。

## 渡すもの

**会話の履歴と、期待する結論は渡さない。**

| 渡す | なぜ |
|---|---|
| 文章（全文。HTML ならそのまま） | 判定の対象 |
| 依頼の種類（作成・修正・レビューのみ） | 修正なら指示の外を変えていないかを見るため |
| 読み手・目的・次にしてほしいこと | 粒度と Q4・Q5・Q7 を判定するため |
| **元の要求と、確認済みの事実**（日付、数値、固有名、決定事項） | これが無いと Q1・Q2・Q3 を判定できない |
| **選んだテンプレート**（あれば） | これが無いと Q8 を判定できない |
| 共通の評価基準・指摘の根拠・判定の決まり（SKILL.md の 3 つの表） | 判定の基準。子が skill を読まずに判定しても同じ基準になるよう、本文に全文を入れる |

足りないものがあれば、レビュアーは最初にそれを返し、判定できない基準を未検証にする。

## 問い

> この文章が、共通の評価基準のそれぞれについて 合格 / 不合格 / 未検証 / 該当なし のどれかを判定し、
> 不合格の箇所ごとに、違反の種類に応じた根拠（書かれたものの誤りは原文の引用、欠落は元の要求か読み手の前提と位置と足す内容、
> 制約の違反は制約と実測値、構成の違反はテンプレートの該当箇所と位置）と、読み手に何が起きるかと、最小の直し方を書け。
> 根拠を示せない指摘は書くな。総合の点数は付けるな。

比べるのは、依頼にそう書かれているときだけで、同じ基準を使う。

## 返す形

1. 足りない材料（あれば）
2. 基準ごとの判定（Q1〜Q9。未検証は、何が無くて確かめられなかったかを添える）
3. 指摘（不合格の箇所ごと）: 種類 / 基準 ID / 根拠 / 読み手に何が起きるか / 最小の直し方
4. 任意の改善提案（違反ではないもの。指摘と混ぜない）

書き直した全文は返さない。判定と指摘を返して終える。さらに委任しない、ファイルを保存しない、送信しない。

## 受け取った後

指摘は主張として扱い、原文と事実で確かめてから直す。採否の決め方は `review-triage` の「進め方」と同じ。
