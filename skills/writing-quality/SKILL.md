# writing-quality

## この skill が防ぐ失敗

| 失敗 | 読み手に起きること |
|---|---|
| 読み手と目的を決めずに書く | 粒度がずれ、知っていることを説明され、知りたいことが無い |
| 要求された項目や、読み手に要る説明が抜ける | 判断や行動ができない。抜けは引用できないので、見落としやすい |
| 確認していないことを書く | 事実として読まれ、後で覆る |
| 確かめていないものを「問題なし」と報告する | 直すべき箇所が残ったまま出る |
| 承認前に送る | 取り消せない |

**文章の質を点数で測らない。**定型句の辞書や文の長さの統計は、直すかどうかの判断を変えなかった（hir4ta-developer での実測）。具体的な基準ごとの合否で見る。

## Step 0 — 依頼の種類を決める

| 種類 | 手元にあるもの | 返すもの |
|---|---|---|
| 作成 | 材料（事実、要求、テンプレート） | 下書きと、基準ごとの判定 |
| 修正 | 元の文章と、直す指示 | 直した文章と、変えた箇所。**指示の外は変えない** |
| レビューのみ | 文章（と要求・事実） | 基準ごとの判定と指摘。**書き直した全文は返さない** |

どれか決まらなければ聞く。

## Step 1 — 読み手と目的を決める

**先に決める。**後から粒度は直せない。会話の文脈で既に明らかなら聞かずに進む。

| 決めること | 例 |
|---|---|
| 読み手 | レビュアー / 同じチームの同僚 / 他部署 / エンジニアでない人 / 社外の相手 |
| 読み手が持っていない前提 | 変更の経緯、専門用語、判断の理由 |
| 読み終えた後にしてほしいこと | 承認する / 顧客に答える / 期日までに返事する / 何もしない |

**この 3 つが埋まらないまま書き始めない。**埋まらない部分が、ユーザーに聞くべきことである。

## Step 2 — テンプレートと規約を探す

**プロジェクトの型が共通の基準より優先する。**PR のテンプレートの探し方は `pr-evidence-pack` の「1. 材料を集める」にある。
テンプレートがあれば、この skill の対象はその各節の中身だけになる。

## Step 3 — 書く・直す

上から順に強い。下は上を上書きしない。

1. ユーザーが明示した指示と例外（「今回は短く」「語調だけ直して」）
2. プロジェクトのテンプレートと規約
3. 会話中に現れているユーザーの語彙と温度感
4. 場面別の差分（下の表）
5. 共通の評価基準（次節）

作成では、元の要求の項目を全部入れる。修正では、指示された点だけを直し、事実・項目・約束を足したり消したりしない。

## 共通の評価基準

| ID | 基準 | 見ること |
|---|---|---|
| Q1 | 事実 | 確認済みの事実・数値・日付・固有名を変えていない。推測を事実として書かず、未確認は未確認と書く |
| Q2 | 要求 | 元の要求の各項目が本文にある |
| Q3 | 除外と制約 | 明示された除外（書かないこと）と制約（字数、宛先、期日）を守っている |
| Q4 | 読み手の知識 | 読み手が持っていない前提を説明し、知っていることを説明し直さない |
| Q5 | 用語 | 読み手が知らない用語に説明がある。言葉は読み手のふだんの語彙に合わせ、硬い言葉や直訳調を避ける |
| Q6 | 図と本文 | 図・表と本文の数値と主張が一致する。複雑な図には短い説明と長い説明がある（[references/figures.md](references/figures.md)） |
| Q7 | 目的と具体性 | 読み手・目的・次にしてほしい返答や判断や行動が読み取れる。抽象的な言葉で済ませず、対象・変更・理由が具体的。目的に寄与しない前置き・定型の挨拶・重複が無い |
| Q8 | 構成 | テンプレートと場面の型を守っている |
| Q9 | 語調 | ユーザーが語調を示しているとき、その語彙と距離感を不必要に均していない。比べる材料（元の文章、明示の指示、同じ相手への実例）が無ければ該当なし。ユーザー固有の文体を推測しない |

### 指摘の根拠

指摘には、違反の種類に応じた根拠を付ける。**どれも示せない指摘は書かない。**

| 種類 | 根拠 |
|---|---|
| 書かれたものの誤り | 原文の引用と、食い違う事実や基準 |
| 欠落 | 元の要求の引用か、読み手が持っていない前提と、説明が要る位置（見出し・段落・直後の文）と、足すべき内容 |
| 制約の違反 | 制約の引用と、実測値（字数など） |
| 構成の違反 | テンプレートの該当箇所と、下書きの位置 |

### 判定

- 基準ごとに **合格 / 不合格 / 未検証 / 該当なし** を付ける。確かめる材料や道具が無かったものは未検証で、**未検証を合格に数えない**
- 総合点は付けない。比べるのは、ユーザーが比べるよう求めたときと、修正の前後を確かめるときだけで、同じ基準を使う
- 任意の改善提案は、違反の指摘と分けて書く

## Step 4 — 確かめる

確かめ方を 3 つに分け、報告にそれぞれの実施と結果を書く。走らせていないものは未検証と書く。

| 確かめ方 | 中身 | 手順 |
|---|---|---|
| 文章の意味 | 共通の評価基準による判定 | 上の節 |
| 機械の検査 | 空の下書き・見出しの欠落・字数・未記入マーカー・重複。**Markdown とテキストだけ** | [references/markdown.md](references/markdown.md) |
| 表示の確認 | HTML や資料を描画して、見え方・図・表を見る | [references/html.md](references/html.md) |

機械の検査は、未対応の形式（HTML など）と読めないファイルでは終了コード 2 で止まる。**止まったことを「問題なし」と読まない。**

## 場面別の差分

| 場面 | 上乗せする条件 |
|---|---|
| Teams・チャット | 結論か返答から入る。共有済みの背景を説明し直さない。挨拶と締めを自動で足さない |
| PR | テンプレートを維持する。変更の理由・内容・確認したこと・影響と未確認事項を具体的に書く |
| Work Item | 説明と受け入れ条件を分ける。受け入れ条件は、検査か確認の手順で合否が決まる文にする（`work-item-ready`） |
| メール | 相手との関係に合わせる。件名・依頼・期限・締めの有無を揃える |
| 設計文書 | 決定・制約・選択肢とトレードオフ・未決事項を構造化する |
| 手順書 | 前提・手順・各手順の確かめ方・失敗したときの戻し方を分ける |
| エンジニアでない人向けの説明・報告 | 何が起きたか・今どうなっているか・読み手が何をすればよいかを先に書く。専門用語は言い換えるか説明を足す |

## Step 5 — 独立のレビュー

**段は文字数ではなく、間違えたときの損失と取り消しやすさで決める。**

| 段 | 対象 | やること |
|---|---|---|
| 1 | すべての文章 | Step 4 と、共通の評価基準による自己点検 |
| 2 | 複数の節がある文章、目安 500 字以上。**または重要な文章**（社外向け、顧客・採用・人事・法務・障害・謝罪、大勢へ送るもの） | 独立した文脈のレビュアーを起動する |

依頼の種類が「レビューのみ」のときは、この skill を使っている本人がレビューし、2 段目の条件に当たるときだけ独立のレビュアーを足す。

2 段目は、custom agent の `prose-reviewer` を `spawn_agent` で起動する。**`fork_turns: "none"` を付ける**（省くと既定の `"all"` で親の会話を引き継ぎ、書いたときの思い込みがレビューに移る）。`task_name` は `prose_review`（2 回目からは `prose_review_r2` のように末尾を変える）。
依頼の形と返す形は [references/review.md](references/review.md)。**会話の履歴と、期待する結論は渡さない。**
`wait_agent` には `timeout_ms: 600000`（10 分）を渡す。3 回続けて時間切れになったか、起動できなかったときは、省いたことを報告に書く。重要な文章は、その代わりに人のレビューを受ける。

### レビュアーとして起動されたとき

判定と指摘を返して終える。さらに委任しない、ファイルを保存しない、送信しない。

## Step 6 — 保存と送信

- **ユーザーが頼んだ場所へのローカルの保存は、そのまま行ってよい。**下書きの検査のための一時ファイルも同じ
- **送信・投稿・PR の作成・Work Item の更新の前は、下書きを見せて承認を待つ。**取り消せないため。ADO へ送るときは `ado` skill の「書く」
- 問いの文言は固定しない。下書きを出した後、本文に混ぜずにユーザーへの発話として短く聞く

## 原則

- **読み手を決めるまで書かない。**粒度は後から直せない
- **テンプレートが基準より強い。**構造は触らず、中身だけを担当する
- **欠落も根拠付きで指摘する。**要求か前提と、位置と、足す内容
- **未検証を合格に数えない。**機械の検査が止まったことも未検証である
- **外へ送る前に承認を受ける。**ローカルの保存は別
